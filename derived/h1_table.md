# Проверка H1

**H1:** при протоколе A (случайное разбиение) метрики выше, чем при B (групповое).

Источники: `derived\results_tfidf.csv`, `derived\results_gine.csv`. Среднее ± стандартное отклонение (ddof=1) по seed. Метрики посчитаны на test, порог выбран на val.

## Метрики

- `mcc`, `f1` — при пороге, выбранном по MCC на val
- `pr_auc`, `roc_auc` — от порога не зависят
- `fpr_at_tpr95` — доля benign, ложно отмеченных как malware, при пороге, который на val ловит 95% malware (меньше = лучше)
- `dedup_*` — те же метрики на test, где каждая последовательность учтена один раз
- `n_seeds` — сколько разбиений (seed) усреднено

## Разница A − B

- `diff_A_minus_B` — среднее A минус среднее B (для `fpr_at_tpr95` меньше = лучше)
- `std_A` / `std_B` — разброс по seed в каждом протоколе
- `diff_to_max_std` — |разница| / наибольший из двух разбросов; меньше 1 — разница укладывается в разброс по seed
- `A_better` — метрика лучше при протоколе A
- `welch_p` — p-value t-теста Уэлча (A и B — независимые выборки по 5 seed); при 5 значениях на группу тест слабый, это ориентир, а не доказательство

## Проверка: TF-IDF только на 1-граммах

Источник: `derived\results_tfidf_ngram1.csv` (блок ngram1 из baseline_tfidf.py). Модель та же (TF-IDF + LogReg, C и порог по val), но признаки — только отдельные API, без порядка вызовов. Средние по seed.

- `*_1to3` — основная модель (n-граммы 1–3), `*_1` — только 1-граммы
- `diff_*` — 1-граммы минус 1–3; около нуля — порядок вызовов почти ничего не добавляет, сигнал в самом наборе API
- `n_seeds` — число seed в основной модели / в проверке

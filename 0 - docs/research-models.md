# Исследование: какие модели взять вместо (или кроме) GNN

> **Поправка от 2026-10-24 (по итогам углублённого исследования).** В этом конспекте AutoRobust описан как набор «вызовы + аргументы» — это неверно: на Kaggle лежат только множества строк (`summary`) без порядка вызовов и аргументов. DMalNet в открытом доступе — только тестовое демо; Avast-CTU reduced тоже без порядка вызовов (для предобучения нужен full); Avast-CTU и WinMET — только malware. Актуальные факты и пересобранный план: [Датасеты и методы детекции malware](<reports/Датасеты и методы детекции malware.md>).

Тема: *разработка и исследование методов выявления вредоносного кода на основе машинного обучения*.
Дата: 2026-10-24. Это мой обзор по собственным знаниям, без поиска свежих статей. Новизну каждого направления нужно проверить по литературе 2024–2026 (раздел 6).

## 0. Исходные ограничения, которые определяют выбор

- **Данные — главное узкое место.** Большие CAPE-корпуса (Avast-CTU, WinMET) содержат только malware, а набор с benign (AutoRobust) один. Значит, нужны методы, которые умеют учиться на неразмеченных или однородных данных.
- **Реальные трассы длинные**: от тысяч до сотен тысяч вызовов. Обрезка до первых N вызовов опасна, потому что начало трассы — это как раз shortcut (см. [datasets-review.md](datasets-review.md)).
- **Простые baseline сильные.** n-gram LogReg даёт AUC ~0,965. Новая модель должна выигрывать там, где baseline ломается: на дрейфе по времени, при атаках уклонения, на новых семействах и малых выборках.
- **«Метод» для диплома** — это не просто другая архитектура, а решение конкретной проблемы с измеримым эффектом.

## 1. Направления (от самых перспективных)

| # | Направление | Какую проблему решает | Новизна | Сложность |
|---|---|---|---|---|
| 1 | **Self-supervised предобучение** на трассах без меток (masked call modeling + contrastive) | мало benign, много неразмеченного malware | высокая, если свои аугментации трасс | средняя |
| 2 | **State-space модели (Mamba / S4)** для длинных трасс | трассы слишком длинные для Transformer (O(n²)) | средне-высокая для API-трасс | средняя–высокая |
| 3 | **Эмбеддинг вызова с аргументами**: API + категория + токены аргументов | только имя API теряет смысл (что именно открыли или записали) | средняя | средняя |
| 4 | **Семантические эмбеддинги API из документации** (описания MSDN → текстовый энкодер) | новые и неизвестные API, перенос между датасетами | высокая | низкая–средняя |
| 5 | **Конформное предсказание с отказом** + детекция дрейфа | модель уверенно ошибается на новом malware | средняя (есть Transcend) | низкая |
| 6 | **Прототипная интерпретируемая сеть** (ProtoPNet для последовательностей) | чёрный ящик; объяснение через «похоже на этот фрагмент» + ATT&CK | высокая | средняя |
| 7 | **One-class / PU-обучение**, в том числе правдоподобие от вашей Diffusion-LM как оценка аномальности | детекция zero-day без примеров нового класса | средняя | средняя |
| 8 | **Устойчивость к атакам вставки API**: adversarial training, randomized deletion smoothing | вставка «мусорных» вызовов ломает детектор | средне-высокая | средняя |
| 9 | Нейронные temporal point processes (Δt между вызовами) | порядок без времени теряет информацию | высокая | высокая; нужны timestamps |
| 10 | Дообучение маленькой LLM (LoRA) на трассах как тексте | — | низкая (модно) | высокая по ресурсам |

**Не рекомендую как основу:**
- CNN по «картинкам» трасс, обычный LSTM/GRU, KAN «ради моды» — банально.
- Ещё одна GNN-свёртка на цепочках i→i+1 — графа там по сути нет.

## 2. Рекомендация: основной метод

### «Самообучаемый энкодер длинных API-трасс с учётом аргументов и надёжным решением»

Комбинирует направления 1 + 2 + 3 + 5. Каждый блок даёт отдельную абляцию, поэтому глава с экспериментами получается сильной.

```
трасса CAPE (тысячи вызовов, несколько процессов)
  └─ эмбеддинг вызова = emb(API) + emb(категория) + энкодер(аргументы: нормализованные пути, ключи реестра, флаги) + emb(процесс)
      └─ энкодер последовательности: Mamba (основной) | Transformer с окнами | BiGRU (baseline)
          ├─ предобучение без меток (на Avast-CTU / WinMET / всех трассах):
          │     • masked call modeling — предсказать скрытые вызовы
          │     • contrastive — две аугментации одной трассы близки, разные трассы далеки
          │       аугментации: вставка benign-подобных вызовов, удаление повторов в циклах,
          │       перестановка независимых процессов, обрезка окон
          └─ дообучение: benign / malware (AutoRobust)
              └─ слой решения: калибровка + конформное предсказание → «malware / benign / не уверен»
```

**В чём новизна (что можно заявить):**
1. **Аугментации, специфичные для API-трасс.** Вставка benign-подобных вызовов как аугментация одновременно даёт устойчивость к атаке уклонения (RQ3).
2. **Использование корпусов без benign** через предобучение. Это прямо решает проблему данных.
3. **Полные трассы без обрезки** за счёт линейной сложности SSM и проверка, что модель не опирается на shortcut «первых вызовов».
4. **Отказ от решения при дрейфе** вместо уверенной ошибки.

**Эксперименты:**
- **Сравнение с baseline:** n-gram + LogReg / LightGBM, BiGRU, Transformer, ваш GINE (как графовый baseline).
- **Абляции:** без предобучения, без аргументов, Transformer вместо Mamba, обрезка до 100/1000 вызовов, без аугментации вставкой.
- **Протоколы:**
  - случайный сплит после дедупликации;
  - **сплит по времени** (обучение на старом, тест на новом) — главный тест;
  - отложенные семейства;
  - малые выборки (1/5/10/25% меток) — здесь предобучение должно выигрывать сильнее всего;
  - атака вставкой 1/5/10/20% вызовов → кривая падения recall.
- **Метрики:** F1, MCC, PR-AUC, FPR при TPR = 95%, ECE; для конформного слоя — доля отказов и ошибка на принятых.

**Практические риски:**
- **`mamba-ssm` с CUDA-ядрами официально работает только на Linux + NVIDIA.** На Windows нужен WSL2 или чистая PyTorch-реализация (медленнее). Запасной вариант: Transformer со скользящими окнами + агрегация.
- **Нужны данные с аргументами и временем (CAPE JSON).** MalBehavD (длина 37, без аргументов) для этого метода не подходит.
- **Объём.** Предобучение на всех трассах WinMET нереально; берите подвыборку или Avast-CTU light.

## 3. Альтернативы, если основной метод не пойдёт

**A. Интерпретируемая прототипная сеть (направление 6).**
- Как работает: энкодер трассы + слой из K обучаемых прототипов. Решение принимается по сходству с прототипами, и каждый прототип проецируется на реальный фрагмент трассы.
- Объяснение имеет вид «эта трасса похожа на фрагмент `VirtualAllocEx → WriteProcessMemory → CreateRemoteThread` (инъекция, ATT&CK T1055)».
- Плюс: выигрышно на защите и закрывает главу об интерпретируемости.
- Бонус: те же прототипы позволяют few-shot классификацию новых семейств.

**B. Детекция как поиск аномалий через генеративную модель (направление 7).**
- Как работает: обучить генератор (вашу Diffusion-LM или небольшую авторегрессионную модель) только на benign, правдоподобие или ошибку реконструкции использовать как оценку «насколько непохоже на нормальное».
- Плюс: переиспользует работу из НИРС, ловит zero-day по построению.
- Риск: такие детекторы часто дают высокий FPR. Нужно честно сравнивать с supervised.

**C. Семантические эмбеддинги API (направление 4)** как самостоятельный вклад. Он небольшой, но чистый.
- Как работает: эмбеддинг API = текстовый энкодер от описания функции в документации.
- Что проверяет: перенос между датасетами с разными словарями и работу с API, которых не было в обучении.
- Хорошо комбинируется с любым из вариантов выше.

## 4. Как это ложится на RQ из [plan-diploma.md](plan-diploma.md)

- **RQ1** (представление и архитектура): энкодер с аргументами и SSM против n-gram, Transformer и GINE.
- **RQ2** (синтетика): заменяется или дополняется вопросом «помогает ли самообучение на неразмеченных трассах так же, как генеративная аугментация». Это прямое и интересное сравнение двух способов бороться с нехваткой данных.
- **RQ3** (устойчивость): сплит по времени, атака вставкой, конформный отказ.

## 5. Порядок работы

1. Датасет: проверить и скачать AutoRobust и Avast-CTU light, прогнать чек-лист из [datasets-review.md](datasets-review.md).
2. Парсер CAPE JSON → таблица вызовов (процесс, API, категория, аргументы, время).
3. Baseline: n-gram + LogReg/LightGBM, BiGRU на новом датасете с честным протоколом.
4. Энкодер с аргументами, сначала Transformer с окнами (проще отладить).
5. Предобучение (masked + contrastive) → дообучение, эксперимент с малыми выборками.
6. Замена на Mamba, абляция по длине трасс.
7. Конформный слой, сплит по времени, атака вставкой.
8. По остатку времени: прототипы для интерпретации.

## еще раз просыми словами, в чем мой метод заключается

Задача. Программу запускают в песочнице и записывают, какие системные функции (API) она вызывает и в каком порядке. По этой записи (трассе) нужно определить, вредоносная программа или нет.

Проблема. Размеченных примеров мало, особенно безопасных программ. А огромные открытые наборы трасс содержат только вредоносные программы, без меток «хорошая или плохая». Обычные модели на таких данных переобучаются и легко обманываются.

Ваш метод в трёх шагах:

Сначала модель учится «читать» трассы без учителя. Ей показывают десятки тысяч неразмеченных трасс и дают задания-головоломки:

угадать скрытые вызовы («закрыли часть слов, угадай пропущенное»);
понять, что две слегка изменённые копии одной трассы — это одно и то же поведение. Изменения такие: вставили лишние безобидные вызовы, убрали повторы.
Так модель сама выучивает, как выглядит нормальное и подозрительное поведение, без единой метки.

Потом её дообучают на небольшом размеченном наборе различать «вредоносное / безопасное». Раз она уже понимает трассы, меток нужно намного меньше.

На выходе модель умеет сказать «не уверена», если трасса совсем не похожа на всё, что она видела. Это нужно для нового malware: модель не ошибается уверенно, а отправляет образец на ручную проверку.

Две детали, которые делают метод сильнее:

Модель смотрит не только на имя вызова, но и на его аргументы, то есть что именно открыли, записали или куда подключились.
Она читает всю трассу целиком, даже если в ней тысячи вызовов. Для этого используется архитектура Mamba, а не обрезка до первых 100 вызовов.
Почему это новизна. Вы используете большие наборы без меток, которые другие не могут применить для такой задачи. Вставка безобидных вызовов при обучении заодно делает модель устойчивой к главному способу обмана детекторов.

Одной фразой: модель сначала самостоятельно учится понимать поведение программ на больших неразмеченных данных, затем дообучается отличать вредоносное от безопасного и умеет признавать неуверенность.



## теперь чуть подробнее, без очень сложной профессионалльной терминологии, базовыми терминами в чем суть метода по шагам. я прочитала твой отчет только примерно поняла что нужно будет делать какие шаги какие модели и тд - мне нужно пояснение всей этой каши

Объясню по порядку, как если бы мы собирали проект с нуля. Сначала общая картина, потом каждый шаг.

Общая идея на примере
Представьте, что вы учите человека находить вредителей среди программ.

Сначала он долго читает огромную кучу записей о поведении программ (без пометок «плохая или хорошая») и привыкает к тому, как программы обычно себя ведут.
Потом ему показывают несколько сотен примеров с ответами («вот эта вредоносная, вот эта нормальная»).
В итоге он хорошо различает их, а когда видит что-то совсем незнакомое, говорит «не уверен, проверьте вручную».
Ваш метод делает то же самое, только вместо человека — нейросеть.

Шаг 1. Данные: трасса поведения
Трасса — это запись того, что делала программа при запуске в песочнице (изолированной «лабораторной» среде). Примерно так:


открыть файл → прочитать файл → создать процесс → записать в реестр → подключиться к сети → ...
Каждая строка — это API-вызов: обращение программы к Windows («открой файл», «подключись к интернету»).

Чтобы метод работал, трасса должна содержать три вещи:

Название вызова, то есть что сделала программа.
Аргументы, то есть над чем сделала. Например, не просто «открыла файл», а «открыла файл C:\Users\...\passwords.txt». Это важная информация.
Порядок вызовов.
Ваш старый датасет MalBehavD хранит только названия, поэтому нужен новый (мы с вами это разбирали).

Шаг 2. Превращаем трассу в числа
Нейросеть не понимает слова, ей нужны числа. Поэтому каждому вызову придаём вектор — набор чисел, который его описывает. Он собирается из трёх кусочков:

Что за вызов (открыть файл, создать процесс …).
К какой группе он относится (файлы, реестр, сеть).
Что в аргументах (путь к файлу, адрес в сети).
Сначала эти числа случайные, но в процессе обучения сеть сама подбирает их так, чтобы похожие вызовы получали похожие числа.

Шаг 3. Предобучение: учимся «читать» без ответов
Это главная часть метода. Берём много трасс без каких-либо пометок (например, десятки тысяч вредоносных из Avast-CTU) и даём сети два упражнения:

Упражнение А. «Угадай пропущенное». В трассе закрываем 15% вызовов и просим сеть угадать, что там было. Чтобы справиться, ей приходится понять, какие вызовы обычно идут друг за другом.

Упражнение Б. «Найди двойника». Берём одну трассу и делаем с ней две слегка изменённые копии: вставляем лишние безобидные вызовы, убираем повторы, вырезаем кусок. Сеть должна понять, что обе копии — одно и то же поведение, а трасса другой программы — другое.

Зачем это нужно:

Сеть выучивает «язык поведения программ», и для этого не нужны метки.
Упражнение Б заодно учит сеть не ловиться на хитрость: вредоносная программа может добавлять мусорные безобидные вызовы, чтобы казаться нормальной. Мы специально обучаем сеть игнорировать такие вставки.
Шаг 4. Дообучение: учимся отличать хорошее от плохого
Теперь берём небольшой размеченный набор (в нём есть и вредоносные, и обычные программы) и обучаем на нём сеть отвечать «вредоносная» или «нормальная».

Сеть уже умеет читать трассы, поэтому ей нужно куда меньше примеров, чем если бы она училась с нуля. Именно это вы и покажете на графике: «при 5% размеченных данных предобученная сеть работает заметно лучше обычной».

Шаг 5. Уверенность: разрешаем отвечать «не знаю»
Обычная сеть всегда выдаёт ответ, даже если видит что-то совершенно незнакомое, причём часто уверенно и неверно. Мы добавляем проверку уверенности. Если трасса не похожа на то, что сеть видела раньше, она отвечает «не уверена», и образец уходит на ручной разбор.

Это важно для реальной защиты: ошибиться молча хуже, чем честно сказать «я не знаю».

Шаг 6. Проверка: сравниваем и ломаем
Чтобы доказать, что метод хорош, его нужно сравнить с другими и проверить в тяжёлых условиях.

С чем сравниваем (простые модели как контрольные):

простая модель, которая просто считает частые комбинации вызовов (n-граммы + логистическая регрессия);
ваша старая GINE;
та же сеть, но без предобучения. Это самое важное сравнение: оно показывает, что именно предобучение даёт выигрыш.
Условия проверки:

Обучаем на старом, тестируем на новом (по времени): так проверяется, справляется ли модель с новым вредоносным ПО.
Мало размеченных данных: оставляем 1%, 5%, 10% меток.
Атака: в вредоносные трассы подмешиваем безобидные вызовы и смотрим, насколько упадёт качество.

Transformer	сеть, которая сравнивает каждый вызов со всеми остальными	запасной вариант основной сети
Mamba	сеть, которая читает трассу по порядку и запоминает главное; хорошо работает с очень длинными трассами	основная сеть
Mamba нужна потому, что реальные трассы бывают очень длинными, а Transformer на таких работает медленно. На Windows можно начать с Transformer или медленной версии Mamba, а метод от этого не меняется.

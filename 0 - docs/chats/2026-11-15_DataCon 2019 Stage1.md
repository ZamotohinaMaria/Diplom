Да, привести DataCon к формату MalBehavD можно. Но «дообучить» модель, обученную на MalBehavD, получится плохо, потому что у двух датасетов почти не совпадают словари API. Я проверила формат и разобрала 300 случайных XML из `train/` (150 black, 150 white).

**Как сделать формат «как у MalBehavD»**

У MalBehavD каждая строка устроена так: `sha256, labels, API₁, API₂, …`. Это уникальные имена API в порядке первого вызова, без повторов. В строке от 2 до 175 вызовов, всего в датасете 291 уникальный API.

Для DataCon нужно поточно разобрать XML, пройти по `<action api_name=…>` в обоих разделах (`start_boot` и `reboot`) и оставить первое появление каждого API. Метки берутся из `safe_type_train.csv` (1 = black, 0 = white). Технически это простой скрипт. 23 ГБ разбираются поточно, в память ничего не грузится.

**Что мешает дообучению**

1. **Словари API почти не пересекаются.** Песочница DataCon перехватывает мало функций: в выборке около 70–80 разных API. Из 291 API MalBehavD встретились только около 50. Если взять модель, обученную на MalBehavD, большая часть её эмбеддингов на DataCon не используется, а для API, которых нет в MalBehavD, у неё вообще нет представлений. Корректно перенести модель можно только на пересечении словарей, а это урезает обе задачи.
2. **Служебные токены песочницы.** В DataCon есть `AnalyzeStart`, `AnalyzeStop`, `TryToAnalyze`, `TooManyBehavior`, `UnpackSelf` и `Fake_*`. Их около 20% всех вызовов. Это не настоящие API, их надо либо выкинуть, либо держать отдельно.
3. **Признаки, которые выдают метку (та же проблема, что у вас в H1).**
   - Раздел `reboot` есть у 61 из 150 вредоносных файлов и только у 2 из 150 безобидных.
   - Размер отчёта (медиана): 1.1 МБ у black и 30 КБ у white.
   - Уникальных API (медиана): 33.5 у black и 16 у white.

   По таким признакам модель может отличать классы, не глядя на смысл поведения. Это стоит проверить так же, как вы проверяли MalBehavD.
4. **У `test/` нет меток.** Это были файлы для отправки на соревнование, поэтому пользоваться можно только `train` (30 000 файлов, классы 1:2). Разбивать придётся самим по вашей схеме: протоколы A и B плюс отдельная validation-выборка.

**Что предлагаю**

Использовать DataCon как второй, независимый датасет. В плане руководителя он как раз стоит на неделе 5. На нём можно заново обучить TF-IDF и GINE и повторить проверку H1 по дублям. Тогда вывод о том, что дубли завышают метрики, будет проверен на двух датасетах. Межъязыковой перенос (обучить на одном, проверить на другом на общих API) можно добавить как необязательный эксперимент.

Если согласны, я напишу конвертер `experiments/convert_datacon.py`. Он запишет `derived/datacon/datacon_train.csv` в схеме MalBehavD и таблицу с длиной последовательности, наличием `reboot` и размером отчёта. Исходную папку он не трогает, запускаете его вы. Скажите только, выкидывать служебные токены (`Fake_*`, `Analyze*` и т.п.) или оставить. Я бы делала два варианта.

Запасной вариант есть. Лучше всего на эту роль подходит датасет Quo Vadis (эмулятор Speakeasy), а самый быстрый в подготовке — датасет Oliveira. Ни одного из них нет в ЛИТЕРАТУРЕ, поэтому выбранный датасет нужно согласовать с Галановым. Из того, что там есть, второй датасет — только DataCon, а Mal-API-2019 он сам отметил как неподходящий (там только malware).

**1. Quo Vadis / Speakeasy (Trizna, AISec 2022) — рекомендую как основной запасной**
- **Состав:** около 93 тыс. 32-битных exe. Benign примерно 35% (≈32,7 тыс.), malware ≈60 тыс. в 7 семействах.
- **Разбиение по времени уже есть:** train за январь 2022, test за апрель 2022. Для честной оценки это плюс, к вашей теме он подходит хорошо.
- **Где лежит:** Hugging Face, `dtrizna/quovadis-speakeasy`. Лицензия Apache-2.0, около 5,5 ГБ, скачивается без регистрации.
- **Минус:** вызовы API получены в эмуляторе, а не в настоящей песочнице, это надо будет оговорить в тексте. Формат — JSON-отчёты, поэтому нужен конвертер, как для DataCon.

**2. Oliveira & Sassi, 2019 (IEEE DataPort, CC BY 4.0) — самый быстрый**
- **Состав:** 42 797 malware и 1 079 goodware. Каждая строка — первые 100 вызовов из песочницы Cuckoo, как и у MalBehavD, вызовы закодированы числами 0–306.
- **Плюсы:** архив весит 2 МБ, это уже готовый CSV, и тема дублей там почти наверняка есть.
- **Минусы:**
  - Безобидных файлов всего 2,5%. Для протокола B групп с безобидными файлами будет мало, а метрики придётся выбирать с учётом дисбаланса (PR-AUC, MCC).
  - Убраны только повторы подряд, а не все повторы, как в MalBehavD. Чтобы схема совпала, при конвертации нужно оставить первое появление каждого вызова.
  - Явной таблицы «число → имя API» на странице нет, поэтому сравнивать словарь с MalBehavD будет трудно.
  - Для скачивания нужна бесплатная учётная запись IEEE.

**Отбросила:**
- Fellicious et al., 2025 (Zenodo): 330 тыс. malware и только 10 тыс. benign, 550 ГБ. Это слишком много для оставшегося срока.
- Набор на IEEE DataPort, собранный из полных данных DataCon (85 тыс. malware и 20 тыс. benign): доступ к нему, похоже, только по подписке.

Чем различаются команды:
- **`huggingface-cli download … --local-dir`** кладёт файлы в указанную папку. Внутри появится ещё служебная подпапка `.cache\huggingface` с метаданными, она маленькая. Если программа напишет, что `huggingface-cli` устарела, ту же команду можно запустить как `hf download …`.
- **`git clone`** создаёт эту папку как отдельный git-репозиторий со своей скрытой `.git`. С LFS она весит примерно вдвое больше, около 11 ГБ.

Выполните только одну из двух команд, я советую `huggingface-cli`. И перед коммитом не забудьте добавить `/QuoVadis Speakeasy` в `.gitignore`.

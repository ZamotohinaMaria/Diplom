**Зачем этот документ.** Руководитель просит собрать один актуальный файл ВКР: взять за основу введение и наработки, перенести аудит данных, описание A/B/C и результаты полной серии C, дать ссылки на результаты в Diplom и перечень оставшихся разделов. Материалы сейчас разбросаны по черновикам, конспектам и отчётам скриптов. Ниже для каждого раздела ВКР указано, что уже написано, из какого файла брать материал, какие числа и где проверять и что ещё нужно сделать. Карта сама по себе не текст ВКР: прозу разделов вы пишете сами.

**Обозначения статуса.**

- **Текст** — есть черновик прозой, его можно переносить и редактировать.
- **Материалы** — есть таблицы, числа и пояснения в конспектах, но прозы для ВКР нет.
- **Нет** — материалов в репозитории нет.
- **План** — раздел зависит от эксперимента, который ещё не выполнен.

# 3. Как связать всё в одну работу

**Сквозная линия.** Каждый раздел отвечает на вопрос, который ставит предыдущий:

1. **Введение:** высокие метрики на открытых датасетах могут быть завышены протоколом; нужен воспроизводимый протокол и честное сравнение.
2. **Гл. 1.5:** известные причины завышения — утечка, смещения, дубли (Arp, Pendlebury, Allamanis); для malware эффект дублей неоднозначен (Zhao) → его надо измерять на конкретных данных.
3. **Гл. 2.2–2.3:** в MalBehavD-V1 много повторов (1601 уникальная трасса из 2570), а в схеме НИРС у 41,8 % оценочных строк была копия в обучении → нужна изоляция.
4. **Гл. 2.4:** три протокола с возрастающей изоляцией: A → B → C. Остальное у всех одинаково (схема фолдов, размеры, баланс), поэтому различия результатов связаны с изоляцией.
5. **Гл. 2.6–2.9:** одна и та же процедура для обеих моделей и всех протоколов: выбор только на validation, test один раз, метрики по всем строкам и по уникальным трассам.
6. **Гл. 3.2:** A против B — насколько меняется оценка, когда убираются общие трассы (H1).
7. **Гл. 3.3–3.6:** C — оценка на новых файлах; сравнение моделей на одних test; где модели ошибаются (RQ1).
8. **Гл. 3.7:** сводка A/B/C — что зависит от протокола, а что нет.
9. **Гл. 3.9 (если будет):** DataCon — проверка, повторяются ли выводы на датасете с другим устройством повторов.
10. **Гл. 4:** как это воспроизвести.
11. **Заключение:** ответы на H1 и RQ1 с той силой утверждений, которую дают данные.

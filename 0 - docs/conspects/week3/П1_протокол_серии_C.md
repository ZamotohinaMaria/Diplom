# 1. Кратко

1. Полная серия C — две модели (TF-IDF 1–3 + LR и GINE e40) на пяти разбиениях C (seed 42–46). Разбиения, настройки, способ выбора порога и метрики те же, что в пилоте.
2. **Пилот seed 42 включается в серию без перезапуска**: код моделей после пилота не менялся, настройки в конфигурации пилота совпадают с настройками серии, GINE считался на CPU (раздел 6).
3. Досчитываются четыре разбиения (seed 43–46) — по одному запуску каждой модели; GINE — только на CPU.
4. В таблицу входят все пять seed. Итог — среднее ± стандартное отклонение по пяти seed и разница моделей на одних и тех же test.

# 2. Данные и разбиения

1. Датасет — MalBehavD-V1, исходный CSV не меняется. До разбиения исключаются 12 строк единственной трассы с конфликтующими метками (5 benign, 7 malware); в разбиение входят 2558 строк.
2. Разбиения — готовые файлы `derived/splits/C_seed42.json` … `C_seed46.json` (неделя 2–8.11, пункт 2), без пересборки. Правила их построения — в конспекте «Проверка разбиения C»: группа объединяет строки с общим `sha256_file` или общей трассой (`seq_hash`), 5 стратифицированных фолдов, фолд 0 — test, фолд 1 — validation, фолды 2–4 — train.
3. Во всех пяти разбиениях между train, validation и test нет общих файлов и общих трасс. Скрипт итоговой таблицы проверяет, что файлы разбиений не изменились после запуска (сверка SHA-256 файла разбиения с записанным в конфигурации).

**Единица оценки.** Модель получает на вход трассу (последовательность вызовов Windows API) и выдаёт вероятность malware для трассы; метрики считаются по трассам. SHA-256 исполняемого файла используется только для группировки при разбиении.

# 3. Модели и настройки

Настройки те же, что в A/B и в пилоте; перебор не проводится.

- **TF-IDF 1–3 + LR** (`experiments/baseline_tfidf.py`, блок main): n-граммы API 1–3, `sublinear_tf`, токен — имя API целиком, регистр сохраняется; логистическая регрессия, `max_iter = 5000`; сетка C = 0,01; 0,1; 1; 10; 100; 1000; 10000.
- **GINE e40** (`experiments/run_gine_splits.py`, параметры по умолчанию): hidden 128, 3 слоя, dropout 0,3, batch 64, 40 эпох, lr 1e-3, weight decay 1e-4, ориентированный граф без skip-рёбер, `max_seq_len = 400`, temperature scaling.

**Сетка C не расширяется**, даже если C снова окажется на краю (в пилоте выбрано C = 10000). Расширение сетки сделало бы настройки серии отличными от пилота, и seed 42 пришлось бы пересчитывать. Если C окажется на краю сетки, это указывается как ограничение.

# 4. Что выбирается на validation

1. Словарь n-грамм и IDF (TF-IDF) и словарь API (GINE) строятся только по train.
2. На validation выбираются: C у логистической регрессии (по максимуму MCC); лучшая эпоха GINE (по MCC при пороге 0,5); температура калибровки GINE.
3. **Порог классификации** выбирается на validation по максимуму MCC; кандидаты — все различные вероятности на validation; при нескольких равных порогах берётся середина их диапазона. Второй порог — наибольший, при котором на validation находится не меньше 95 % malware (для FPR@TPR95).
4. Test используется один раз, когда всё зафиксировано. Ни настройки, ни порог, ни эпоха по test не выбираются.

# 5. Порядок запуска

1. Seed 43–46 запускаются **по одному разу** для каждой модели.
2. **GINE — только на CPU** (`--device cpu`), как в пилоте. На GPU результат при том же seed не повторяется: на копии `B_seed42` два запуска дали MCC 0,854 и 0,894; на CPU два запуска совпали полностью. Итоговый скрипт серии проверяет по конфигурациям, что все пять запусков GINE шли на CPU, и иначе останавливается.
3. Перезапуск допускается только при технической ошибке (скрипт упал, не хватило памяти); причина записывается в `EXPERIMENTS.csv`. Результат на test поводом для перезапуска не является.
4. **В итоговую таблицу входят все пять seed**, ни один не исключается — в том числе seed 44, где одна группа составляет 64,1 % malware test.

Для серии в скрипты моделей добавлен только параметр `--run-name` — имя серии, от которого зависят имена файлов результатов и логов (`results_series_C_*.csv`). Без этого параметра скрипты пишут в те же файлы, что раньше, поэтому команды A/B и пилота воспроизводят прежние результаты. Логика обучения и оценки не менялась, а сам параметр в настройки конфигурации не попадает. При сборке таблицы скрипт ещё раз сравнивает настройки всех пяти seed с пилотом и останавливается при расхождении.

# 7. Метрики

**Для каждого seed и каждой модели:**

| Метрика | Как считается |
|:---|:---|
| MCC | при пороге по MCC с validation — основная метрика |
| F1 | при том же пороге, класс malware положительный |
| PR-AUC, ROC-AUC | по вероятностям, от порога не зависят |
| FPR@TPR95 | доля benign, ложно отмеченных как malware, при пороге, который на validation находит 95 % malware |
| Ложные тревоги (FP) | число benign test, отмеченных как malware, при пороге по MCC |
| Пропуски (FN) | число malware test, отмеченных как benign, при пороге по MCC |
| Время обучения | у TF-IDF — вместе с подбором C по всей сетке, у GINE — 40 эпох с оценкой на validation |

**Два способа подсчёта** — каждая метрика, включая FP и FN, приводится дважды:

- **по всем строкам test** (512 строк);
- **по уникальным трассам test**: каждая трасса (`seq_hash`) учитывается один раз. Одинаковые трассы дают модели одинаковый вход, поэтому вероятность у них одна. Это убирает вес крупных групп одинаковых трасс (до 164 строк в одной группе).

**Сводка по серии:**

1. Среднее ± стандартное отклонение (ddof = 1) по пяти seed — для MCC и F1 (основные) и для остальных метрик; по всем строкам и по уникальным трассам.
2. **Сравнение моделей на одних и тех же test**: для каждого seed считается разница GINE − TF-IDF (MCC, F1, FP, FN, по всем строкам и по уникальным трассам), затем среднее ± std разниц и число seed, где лучше каждая модель.
3. FP и FN — по каждому seed и суммой по пяти seed, с числом benign и malware в test.

# 8. Как интерпретировать

- Пять seed — это описание разброса оценки, а не проверка статистической значимости. Вывод о превосходстве модели формулируется только как «на всех пяти test» или «на k из пяти».
- Причины ложных тревог GINE остаются гипотезами до отдельной проверки.
- Seed 44 заранее отличается от остальных: группа из 164 одинаковых трасс malware целиком попадает в test. Метрики по всем строкам на этом seed сильно зависят от одной группы, поэтому для него важнее метрики по уникальным трассам.
- Средние A/B приводятся рядом только для контекста: это другие разбиения, а GINE в A/B считался на GPU.

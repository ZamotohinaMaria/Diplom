# 2. Цель и правила (зафиксированы до запуска)

**Цель.** Оценка на исполняемых файлах, которых не было в обучении. В протоколе B точные трассы не пересекаются, но разные трассы одного файла могут оказаться в train и test; протокол C это устраняет.

**Правила.**

1. **Связь записей.** Две строки относятся к одной группе C, если у них одинаковый `sha256_file` или одинаковый `seq_hash`. Связи транзитивные: если файл X дал трассы T1 и T2, а трасса T2 есть и у файла Y, то X и Y — в одной группе. Группы строятся как компоненты связности (union-find).
2. **Конфликтная группа.** Как в A и B, до группировки исключаются 12 строк единственной трассы с метками benign и malware. После этого каждая группа должна быть одного класса; при нарушении скрипт останавливается, метки не исправляются.
3. **Идентификаторы файлов.** `sha256_file` нормализуется (пробелы по краям, нижний регистр); корректный id — 64 шестнадцатеричных символа. Строки с отсутствующим или некорректным id связываются только по трассе.
4. **Схема разбиения** та же, что в A/B: 5 стратифицированных фолдов, фолд 0 — test, фолд 1 — validation, фолды 2–4 — train. Группы целиком раскладываются жадным алгоритмом LPT внутри каждого класса.
5. **Разбиение для пилота** — seed 42; seed 43–46 используются для проверки устойчивости.
6. **Критерии пригодности** (для каждого seed):
   - К1 — крупнейшая группа класса не больше одного фолда этого класса (строк класса / 5); иначе схема невозможна;
   - К2 — test и validation содержат от 486 до 538 строк (512 ± 5 %);
   - К3 — доля malware в каждой части от 45 до 55 %.

# 7. Ограничения

- **Концентрация крупных групп.** Группа из 164 одинаковых трасс (162 файла) целиком попадает в одну часть; при seed 44 она составляет 64,1 % malware test. Метрики по всем строкам test в таком разбиении в значительной мере отражают ответ модели на одну трассу, поэтому в пилоте нужно приводить также метрики по уникальным трассам.
- **Новые файлы — не новые семейства.** C гарантирует, что файлы test отсутствуют в train, но похожие (не идентичные) трассы файлов одного семейства могут быть и в train, и в test. Оценка на новых семействах требует информации о семействах, которой в датасете нет.
- **Идентичность файла определяется только по `sha256`.** Модифицированные или переупакованные варианты одной программы имеют разные хэши и считаются разными файлами.
- **Один seed в пилоте.** Пилот на `C_seed42` — проверка реализуемости; статистических выводов по одному разбиению не делается.
